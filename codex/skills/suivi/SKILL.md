# $suivi — Todolist (Codex)

**Language**: reply to the user in their language (the one they write in). Task content (titles, steps, notes)
is written in the user's language as well.

Tarmac runs locally (`http://127.0.0.1:7777` by default) and exposes the MCP server `tarmac` (tools `suivi_*`,
declared in `~/.codex/config.toml` by `tarmac setup`). Two places kept in step: the Tarmac database (truth, shown
in Tarmac's Todolist view) and the versioned `Todolist/` copy in the repo. The claude.ai artifact of Claude Code
users is not available from Codex: Tarmac keeps it in step on the Claude side.

## Landmarks

- **projectId**: `owner/repo` of the git remote (`git remote get-url origin` → `acme/shop`), otherwise the name
  of the root folder. If it exists, `Todolist/suivi.config.json` at the git root is authoritative.
- **Source of truth**: Tarmac (`suivi_get`).
- **Repo copy**: `Todolist/<copyFile>` (default `suivi.json`), regenerated by `suivi_write_copy`. Never edit it by
  hand.

## Writing a task — on every creation, check, note, switch to "to test"

1. `suivi_upsert_task` (or `suivi_set_done`) → returns the full task (`id`, `num`, `order`, `rev`, `updatedAt`…).
2. `suivi_write_copy`.

Rules: every user request becomes a task; a remark on a tested task creates a lettered subtask (`parent` = the
task's id → 7.32a right below it); a handled task becomes `toTest: true`, and is only checked (`done`) after the
user validates it; never delete (`archived: true`); never put a secret or a `.env` value in a task.

Tasks **marked for an agent** (▶ button in Tarmac: `requestedAt` set): when the session-start hook lists their
numbers, offer them in one line and start only if the user confirms. A message "Handle task <num> … from the
<projectId> tracker" sent by the ▶ button is the user's request: read the task with `suivi_get`, do it, then
`suivi_set_done` with `toTest: true` (Tarmac clears the mark). Never set `requestedAt` yourself.

## $suivi init

1. Determine `projectId`, the git root, the name. `suivi_list_projects`: if the project already exists, go to
   `$suivi sync`.
2. `suivi_register_project` with `projectId`, `name`, `paths: [<absolute git root>]` (no `theme`: Tarmac detects
   the brand), `title` ("Project tracker" or better), `subtitle`.
3. Show the chosen brand to the user (primary color, heading font); fix it with `suivi_register_project` +
   `theme` if needed.
4. Create `Todolist/suivi.config.json` (`projectId`, `name`, `brand`, `title`, `subtitle`, `file: "suivi.json"`,
   `theme`) and `Todolist/README.md` (tracking managed by Tarmac, do not edit the copy by hand), then
   `suivi_write_copy`.
5. Tell the user the Todolist is visible in Tarmac (project panel → Todolist tab). Past work worth tracking?
   Offer `$suivi import`.

## $suivi sync

`suivi_get` then `suivi_write_copy`; sum up in one line (tasks, done, to test). The artifact side (Claude) is
synced by Tarmac and Claude sessions, not from Codex.

## $suivi theme

Show the saved brand (`suivi_get` → `project.theme`); suggest a fix (primary color `#RRGGBB`, Google Fonts);
save it in `Todolist/suivi.config.json` and `suivi_register_project`.

## $suivi restructure — split, merge or renumber phases

Task ids never change; only `phase`, `phaseTitle`, `num` and `order` move.
1. `suivi_get` (archived included); propose the new phases (number, title) and where each task of a phase to
   split goes (by title, `why`, steps; ask when in doubt).
2. Plan: `phases` (`{from, to}`, whole phases renumbered), `moves` (`{taskId, phase}`, top-level tasks; subtasks
   follow their parent), `titles` (`{phase, title}`), optional `compact: true` (renumber touched phases 1..N).
3. `suivi_restructure` with `dryRun: true`; show the phases and the old → new numbers (`mapping`), wait for the
   user's OK. Then the same call without `dryRun`, then `suivi_write_copy`. The artifact side is caught up by the
   next Claude `/suivi sync`.

## $suivi audit — set already-coded tasks to "to test"

1. `suivi_get` with `includeDone: false`; keep untreated tasks (not done, not `toTest`, not archived).
2. For each, look for evidence: `git log --all --oneline -i --grep "<num>\b"` (and its id), commits in its
   `sources`, otherwise the code matching its title and steps. Verdict: coded (all steps, committed), partial,
   not coded.
3. Show the coded and partial lists, wait for the user's OK; then `suivi_upsert_task` with `toTest: true`, a note
   "Audit: coded in <sha> …" (appended, never overwriting) and the commit in `sources`; never `done`. Then
   `suivi_write_copy`.

## $suivi import — fill the tracker from past work

1. Collect: the project's past Codex sessions (Tarmac: `GET /api/projects/<id>/codex-sessions`), and `git log`.
2. Extract candidate tasks `{ title, why, steps, status, doneAt, sources[] }` (sources: session id, commit,
   short quote).
3. Merge: dedupe, phases by theme, chronological order, numbers `<phase>.<n>`.
4. Status: **done** only with a proof (delivered, validated by the user or committed); otherwise **to do**.
5. **Review before writing**: show the list to the user and wait for their OK. Nothing is written before that.
6. Idempotence: do not recreate an existing task (match by sources and by title).
7. Write after the OK: `suivi_upsert_task` for each task, then `suivi_write_copy`.
